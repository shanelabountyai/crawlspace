| D-23 | Tests need the local test server on 127.0.0.1, which the guard refuses | (a) injectable resolver + policy; tests allow loopback only for `*.test` hostnames, CS-03 uses the real policy, (b) env flag that disables the guard | **(a)** — no switch in production code can turn the guard off | `tests/helpers/site-server.ts` |
| D-24 | robots.txt edge cases for CrawlspaceBot | (a) 5xx → don't scan (RFC 9309), `/` disallowed → don't scan, 4xx → allow, (b) scan anyway and flag | **(a)** — be a good citizen; the scan says why it stopped | `src/lib/crawl/crawl.ts` |
| D-25 | Fix-list LLM in the Phase 3 build run (owner rule 2026-11-15: no live LLM calls, no API keys) | (a) model behind a `FixListModel` interface; tests and e2e use committed recorded responses (incl. invented checks/evidence the validator must reject); live Anthropic adapter written but never called here, (b) template-only, no adapter, (c) call the API with a key | **(a)** — the validator and fallback are proven offline; the live path is one env var away | owner hand step: set `ANTHROPIC_API_KEY` on the Mac and run a scan (`src/server/anthropic-model.ts`) |
| D-26 | Prisma CLI cannot download its engines in the agent sandbox (binaries.prisma.sh refused), so `prisma migrate` cannot run here | (a) keep Prisma (D-03): Prisma Client 7 + better-sqlite3 driver adapter, hand-written SQL in `prisma/migrations/`, applied on startup by a small migrator, CI checks it against the schema with `prisma migrate diff`, (b) drop Prisma for raw SQLite, (c) Postgres | **(a)** — honours D-03 and still gets a drift check where engines can download | switch the migrator to `prisma migrate deploy` once engines are available everywhere (`src/server/db.ts`) |
| D-27 | The e2e must crawl a fixture site on 127.0.0.1, which the SSRF guard refuses (D-23 forbids an env switch) | (a) crawl options injected in-process through a `globalThis` symbol that only `scripts/e2e-server.ts` sets (`.test` → 127.0.0.1 only, the D-23 test policy), (b) env flag honoured outside production, (c) scan fixtures from disk in the web UI | **(a)** — nothing reachable from env, config or HTTP can widen the guard; (c) would skip the crawler | `src/server/crawl-options.ts` |
| D-28 | Fix-list validator rules beyond PRD "drop items citing a check ID or URL not in the input" | (a) drop an item if its `checkId` is not a failed/partial input check, if any cited URL (field or prose) is not an input evidence URL, or if its prose names a check ID not in the input; unparseable output → all templates; every drop counted by reason and shown on the report, (b) only check the `checkId` field | **(a)** — invented evidence in prose is as misleading as in a field | `src/lib/fixlist/validate.ts` |
| D-29 | Running and keeping web scans | (a) in-process queue, one crawl at a time, ≤ 5 waiting (HTTP 429 beyond), scans left queued/running at restart marked failed; store scorecard + fix list + crawl summary, not page HTML, (b) a separate worker + job table, (c) store full snapshots | **(a)** — single-node tool, not deployed in v1 (D-08); no third-party HTML kept at rest | `src/server/scan-service.ts`, `QUEUE_LIMIT` |
| D-30 | Fix-list ranking and coverage | (a) validated model items in the model's order first, then a template for every failed/partial check the model did not cover, ranked by points lost (weight × (1 − status value)), ties in rubric order, (b) templates only fill when the model returns nothing | **(a)** — the list always covers every problem; the model can reorder only what it actually addressed | `src/lib/fixlist/generate.ts` |
